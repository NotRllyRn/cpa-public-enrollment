# Prototype boundaries

- **Browser → OpenAI:** device-code creation and polling only, via `browserAuth` in `page.go`. **Go → OpenAI:** exchange the approved authorization code + verifier using the fixed device callback. Access/refresh tokens never enter JavaScript. No token-upload endpoint, server polling adapter, refresh worker, scheduler or proxy rotation.
- Authorization expires 15 minutes after session creation: no creation, polling or approval is accepted after that fixed deadline. Unfinished `idle`/`creating`/`waiting` flows become explicit `expired` state, clear their device details, and stop browser polling. **Reset session to review access** clears that session's local pending files and rotates cookie and CSRF for expired, missing, error, operator-review, or duplicate sessions; it does not create a provider code. Saving/verifying and successful complete sessions cannot be reset. In-flight saves are never pruned; terminal results remain for 5 minutes after completion. Expired unfinished sessions are retained for 5 minutes after their deadline. Activity extends neither window. The secure browser-session cookie can outlive server state: missing sessions return structured `session_lost` and warn about service updates/possible saves, never silently restart. Reset does not undo a CPA import or revoke access. Losing the cookie itself cannot be distinguished from a new visitor and cannot recover ownership of local pending files.
- Secure/HttpOnly/SameSite cookies, exact HTTPS Origin, JSON and CSRF checks protect mutations. Explicit recovery of missing server state cannot validate its old CSRF and relies on exact Origin + JSON; it rotates both cookie and CSRF and never imports credentials. Web Locks serializes bootstrap/recovery; stale cross-tab CSRF triggers session synchronization, not a retried mutation. Server reservations and poll leases coordinate tabs. No localStorage. Creation reservations expire after 45 seconds. A lost response may already have created a provider code: this is **not exactly-once** creation. **Check sign-in status** resumes polling after connection errors without creating another code. Process restart or successful native replacement may lose sessions. In-memory device details expire, never go into URLs or logs.
- Automatic sign-in checks run only while the tab is visible, targeting a 3-second interval (also the default/minimum). Longer provider intervals, rate limits, `slow_down`, and numeric/date `Retry-After` delays take precedence. The waiting badge uses the server's next-check deadline, not a fixed 3-second display, and shows “Checking your sign-in” during a check. Returning to a visible tab synchronizes current state without a catch-up burst. There are no new automatic status or OpenAI requests while hidden; an already-started request and delivery of its approval/pending result may finish safely. A pending result releases its exact server lease and sets the next deadline; the separate 20-second in-flight safety deadline is not a normal cooldown. Tabs cannot share or replace a live lease. An unconfirmed expired check requires recovery, never automatic replay of a possibly consumed approval. Transient delivery retries may continue in the background, but periodic status checks do not.
- Only one save is admitted at a time; overlapping approvals get a busy response. The browser retries transient delivery failures briefly, then pauses; structured session conflicts are not retried. Busy/expired proofs may need a fresh flow only after confirming no save began. Saves are serialized. Go checks pending account ID plus normalized email before durably writing another pending credential, checks managed inventory before one CPA upload, then checks runtime identity + `source=file` + `adopted=true`. CPA is the sole refresh owner. Ambiguous writes are **never reuploaded**, including after restart. Pending secrets, including uncertain uploads and legacy unowned records, expire after 10 minutes at startup, in the periodic loop, and before save checks; active saves hold the adoption lock and cannot be cleaned. Reset deletes only filenames owned by the hash of the current high-entropy cookie, even after restart; legacy files expire by age only. Neither cleanup nor reset deletes CPA-adopted credentials or rolls back imports. There is no automatic recovery/replay UI. Other CPA writers are not transactionally coordinated.
- Identity fields are decoded from the ID JWT returned directly by the fixed TLS token endpoint and required fields are checked. This is **not cryptographic JWT signature/issuer/audience verification**. This prototype relies on that trusted token response.
- Real browser login, actual POST CORS behavior, and deployed CPA import are untested. OPTIONS allowing `*` does not prove a working login. Test these manually on an authorized test account behind HTTPS, including two tabs, reload, CORS/network failure and ambiguous import. Modern Web Locks / fetch timeout support is required. Add reverse-proxy abuse/rate limits before public use; local session count is capped at 2048, not a complete abuse defense. Pending cleanup failures need operator storage repair; see [retention and reset](native.md#replacement-and-recovery).
