# Prototype boundaries

- **Browser → OpenAI:** device-code creation and polling only, via `browserAuth` in `page.go`. **Go → OpenAI:** exchange the approved authorization code + verifier using the fixed device callback. Access/refresh tokens never enter JavaScript. No token-upload endpoint, server polling adapter, refresh worker, scheduler or proxy rotation.
- Authorization expires 15 minutes after session creation: no creation, polling or approval is accepted after that fixed deadline. The same session and secure cookie remain valid for a fixed additional 5 minutes for status/resume only, covering the bounded 90-second save and result polling. Activity never resets either deadline; cleanup removes sessions at the end of that grace. Secure/HttpOnly/SameSite cookies, exact HTTPS Origin, JSON and CSRF checks protect mutations. Web Locks serializes initial cookie setup; server reservations and poll leases coordinate tabs. No localStorage. Creation reservations expire after 45 seconds. A lost response may already have created a provider code: this is **not exactly-once** creation. Reload resumes the shared flow; restart loses sessions. In-memory device details expire, never go into URLs or logs.
- Only one save is admitted at a time; overlapping approvals get a busy response. The browser retries delivery briefly, then pauses. Busy/expired proofs may need a fresh flow after confirming no save began. Saves are serialized. Go durably writes a pending credential before one CPA upload, checks managed/pending account IDs, then checks runtime identity + `source=file` + `adopted=true`. CPA is the sole refresh owner. Ambiguous writes are **never reuploaded**, including after restart. `operator-review`, duplicate or interrupted saves retain secret files: an operator must privately reconcile CPA inventory and remove obsolete pending files. There is no automatic recovery/replay UI. Do not blindly retry enrollment after an uncertain save. Other CPA writers are not transactionally coordinated.
- Identity fields are decoded from the ID JWT returned directly by the fixed TLS token endpoint and required fields are checked. This is **not cryptographic JWT signature/issuer/audience verification**. This prototype relies on that trusted token response.
- Real browser login, actual POST CORS behavior, and deployed CPA import are untested. OPTIONS allowing `*` does not prove a working login. Test these manually on an authorized test account behind HTTPS, including two tabs, reload, CORS/network failure and ambiguous import. Modern Web Locks / fetch timeout support is required. Add reverse-proxy abuse/rate limits before public use; local session count is capped at 2048, not a complete abuse defense. Pending secrets need operator retention/backup policy.
