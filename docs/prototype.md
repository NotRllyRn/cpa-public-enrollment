# Prototype boundaries

- **Browser → OpenAI:** device-code creation and polling only, via `browserAuth` in `page.go`. **Go → OpenAI:** exchange the approved authorization code + verifier using the fixed device callback. Access/refresh tokens never enter JavaScript. No token-upload endpoint, server polling adapter, refresh worker, scheduler or proxy rotation.
- Authorization expires 15 minutes after session creation: no creation, polling or approval is accepted after that fixed deadline. Unfinished `idle`/`creating`/`waiting` flows become explicit `expired` state, clear their device details, and stop browser polling. **Start new sign-in** rotates cookie and CSRF only for expired or missing sessions; it does not itself create a provider code. Saving/verifying and retained terminal/operator-review sessions cannot be reset. In-flight saves are never pruned; terminal results remain for 5 minutes after completion. Expired unfinished sessions are retained for 5 minutes after their deadline. Activity extends neither window. The secure browser-session cookie can outlive server state: missing sessions return structured `session_lost` and warn about service updates/possible saves, never silently restart. If saving or review was involved, contact the operator before another sign-in. Losing the cookie itself cannot be distinguished from a new visitor.
- Secure/HttpOnly/SameSite cookies, exact HTTPS Origin, JSON and CSRF checks protect mutations. Explicit recovery of missing server state cannot validate its old CSRF and relies on exact Origin + JSON; it rotates both cookie and CSRF and never imports credentials. Web Locks serializes bootstrap/recovery; stale cross-tab CSRF triggers session synchronization, not a retried mutation. Server reservations and poll leases coordinate tabs. No localStorage. Creation reservations expire after 45 seconds. A lost response may already have created a provider code: this is **not exactly-once** creation. **Check sign-in status** resumes polling after connection errors without creating another code. Process restart or successful native replacement may lose sessions. In-memory device details expire, never go into URLs or logs.
- Only one save is admitted at a time; overlapping approvals get a busy response. The browser retries transient delivery failures briefly, then pauses; structured session conflicts are not retried. Busy/expired proofs may need a fresh flow only after confirming no save began. Saves are serialized. Go durably writes a pending credential before one CPA upload, checks managed/pending account ID plus normalized email, then checks runtime identity + `source=file` + `adopted=true`. CPA is the sole refresh owner. Ambiguous writes are **never reuploaded**, including after restart. `operator-review`, duplicate or interrupted saves retain secret files: an operator must privately reconcile CPA inventory and remove obsolete pending files. There is no automatic recovery/replay UI. Do not blindly retry enrollment after an uncertain save. Other CPA writers are not transactionally coordinated.
- Identity fields are decoded from the ID JWT returned directly by the fixed TLS token endpoint and required fields are checked. This is **not cryptographic JWT signature/issuer/audience verification**. This prototype relies on that trusted token response.
- Real browser login, actual POST CORS behavior, and deployed CPA import are untested. OPTIONS allowing `*` does not prove a working login. Test these manually on an authorized test account behind HTTPS, including two tabs, reload, CORS/network failure and ambiguous import. Modern Web Locks / fetch timeout support is required. Add reverse-proxy abuse/rate limits before public use; local session count is capped at 2048, not a complete abuse defense. Pending secrets need operator retention/backup policy.
